# Изолированная демонстрационная версия PhoneBooks

DEMO — отдельная локальная PWA для покупателей. Она собирается из тех же экранов
и доменных функций, что полная версия; включить её параметром URL невозможно.
Рабочий сайт https://bikmako.github.io/phonebooks/ и его публикация не изменяются.

## Сборки и хранилища

| Объект | Полная версия | Демо |
| --- | --- | --- |
| Команда | `npm run build` | `npm run build:demo` |
| Результат | `dist/` | `dist-demo/` |
| IndexedDB v1 | `phonebooks` | `phonebooks-demo` |
| Тема | `phonebooks.theme` | `phonebooks.demo.theme` |
| Черновики | `phonebooks.draft.*` | `phonebooks.demo.draft.*` |
| Legacy | прежняя миграция | миграция пропускается до чтения localStorage |
| Метаданные | в основной IndexedDB | только в демобазе |
| Service Worker | `sw.js` | `sw-demo.js` |
| Кеш | `phonebooks-v9-*` | `phonebooks-demo-v9-*` |
| PWA id | `./` | `./?app=phonebooks-demo` |

Демо очищает только собственные кеши и ищет офлайн-ресурсы только в своём кеше.
Сборка в demo-режиме не меняет `dist/`. Исходные статические файлы старой версии,
`public/sw.js` и workflow `.github/workflows/deploy-pages.yml` остаются прежними.
В полной сборке генератор демоданных заменяется обычным пустым инициализатором.
Демо отказывается запускаться на всём origin `https://bikmako.github.io` ещё до
открытия IndexedDB, установки темы и регистрации Service Worker.

**Другой репозиторий в том же аккаунте GitHub Pages без отдельного домена не
обеспечивает другой origin:** `bikmako.github.io/phonebooks-demo/` также запрещён.
Другой путь, hash или query недостаточен. Нужен отдельный домен, поддомен или
новый сайт на другом HTTPS origin. Новый URL не требует переноса данных.

## Начальные данные и работа

При отсутствии демобазы автоматически создаются 14 моделей смартфонов: семь
проданных, остальные на складе, в резерве или ремонте. Есть восемь записей продаж
(включая одну отменённую), завершённый ремонт, пять видов аксессуаров с партиями,
четыре продажи аксессуаров, списание, три расхода, два счёта, перевод,
пополнение, снятие и журнал изменений. IMEI и номера контрагентов в исходных
данных пустые, названия контрагентов явно демонстрационные.

Покупки, продажи, ремонт, остатки партий и аудит создаются обычными доменными
функциями. Даты операций отсчитываются от первого запуска или явного сброса,
чтобы статистика за последние 30 дней содержала примеры. При повторном открытии
сохранённые тестовые изменения остаются; автоматического сброса нет.

Контрольные суммы за весь исходный период:

- Выручка: 328 820 ₽, себестоимость проданного: 261 540 ₽.
- Валовая прибыль: 67 280 ₽; расходы: 15 350 ₽; списание аксессуаров: 560 ₽.
- Чистая прибыль: 51 370 ₽.
- Закупки телефонов: 404 500 ₽; аксессуаров: 21 700 ₽; ремонт: 1 500 ₽.
- Касса: 653 660 ₽; расчётный счёт: 367 110 ₽; всего: 1 020 770 ₽.
- Остаток аксессуаров: 72 шт.

В настройках «Сбросить демо» требует подтверждения, отменяет несохранённые правки,
дожидается текущих записей и одной транзакцией заменяет демосостояние, очищает
демокопии и метаданные. Тема и черновики демо также удаляются. Полная база и её
ключи не открываются и не очищаются. Старые вкладки не могут записать устаревшее
состояние поверх сброса: действует существующая проверка версии состояния.
Повреждённую демобазу можно восстановить отдельной подтверждаемой кнопкой на
экране ошибки запуска, без скачивания диагностических данных.

Импорт, экспорт, точки восстановления, полные снимки, восстановление прерванного
импорта и скачивание JSON запрещены на уровнях контекста и storage API. Парсер
файлов переноса и сборщик экспортного формата также отклоняют вызовы. Обычная
валидация локального состояния работает. Облачные сервисы и подписка не добавлены.

## Контакт продавца

1. Скопировать `.env.demo.example` в `.env.demo.local`.
2. Указать действительный контакт в `VITE_DEMO_SELLER_CONTACT`.
   Поддерживаются `https:`, `mailto:` с одним адресом без query и `tel:`.
   Это публичная конфигурация: секреты сюда не помещать.
3. Пересобрать `npm run build:demo`. Изменение контакта требует новой сборки.

Без контакта или с неподдерживаемым значением CTA «Купить полную версию» открывает
понятное окно с предложением обратиться к продавцу, предоставившему демо.
Вымышленных ссылок и неработающего `href` нет. Кнопка с HTTPS-контактом открывает
новую вкладку с `noopener noreferrer`. Данные учёта в ссылку не подставляются.

## Точные шаги публикации на отдельном адресе

Публикацию выполняет владелец после проверки PR. Команды ниже готовят только
локальные файлы; текущий GitHub Pages workflow запускать для DEMO не нужно.

```bash
git switch feat/isolated-sales-demo
git pull --ff-only
npm ci
cp .env.demo.example .env.demo.local
# Заполнить VITE_DEMO_SELLER_CONTACT реальным контактом продавца.
npm test
npm run build
npm run build:demo
npm run test:builds
npm run preview:demo -- --port 4175
# Проверить http://localhost:4175/; Ctrl+C завершает локальное превью.
```

Вариант отдельного хостинга без изменения GitHub Pages и действующего Netlify:

1. В Cloudflare открыть Workers & Pages → Create application → Pages →
   Upload assets / Direct Upload. Создать **новый** проект с отдельным именем.
   Не выбирать существующий проект и не подключать текущий production-сайт.
2. В новый проект загрузить **содержимое только `dist-demo/`**: `index.html`,
   `sw-demo.js`, `manifest.webmanifest`, `assets/`, `scanner-assets/`, `icons/`
   и остальные файлы каталога. Не загружать репозиторий, `dist/`, `.env*` или
   старую готовую сборку из корня. Можно загрузить папку через веб-интерфейс.
3. Выполнить публикацию нового проекта и взять выданный ему HTTPS URL из панели.
   Убедиться, что его `location.origin` отличается от
   `https://bikmako.github.io` и от origin полной версии, если она размещена ещё
   где-либо. Этот URL и будет отдельной демонстрационной ссылкой.
4. На выданном URL проверить метку «ДЕМО», покупку/продажу, корректный контакт CTA,
   подтверждение сброса, отсутствие переноса данных и доступность `sw-demo.js`.
   В DevTools → Application должна быть только демобаза и демокеш.
5. Дождаться загрузки офлайн-оболочки, открыть сканер, разрешить камеру.
   Затем отключить сеть, перезагрузить страницу и повторить закупку/сканирование.
   На iPhone открыть URL в Safari и при необходимости «Поделиться» →
   «На экран Домой»: имя приложения — PhoneBooks ДЕМО.

Сборка использует относительный base и подходит для корня нового origin.
Для подпапки на **другом** origin: `npm run build:demo -- --base /demo/`, затем
разместить всё содержимое `dist-demo/` именно в этой подпапке.
Не размещать DEMO под `https://bikmako.github.io/` и не заменять файлы рабочего сайта.

## Проверки и ограничения

```bash
npm test
npm run build
npm run build:demo
npm run test:builds
npx playwright install --with-deps chromium firefox webkit
npm run test:demo:browser
npm run test:browser -- --project chromium-desktop --project android-chromium --project iphone-webkit --project firefox-desktop
```

Демо Playwright использует отдельные порт 4175, base `/demo/` и папку отчётов
`test-results-demo/`, полная версия — 4173/4174 и `test-results/`.
Проверки охватывают и узкий iPhone SE, и iPhone 13 (WebKit), Android Chromium,
настольный Chromium; реальные OCR и Code128 распознаются из тестовых изображений
без сети. Набор основной версии дополнительно проверяет захват кадров камеры,
освобождение потоков, QR, восстановление резервных копий и финансовые ремонты.

Первый визит требует сети для загрузки ресурсов (~локальные OCR/WASM ассеты);
после установки Service Worker оболочка и сканер работают офлайн. Камера требует
HTTPS и разрешения браузера. Эмуляция WebKit не заменяет проверку физической камеры
на настоящем iPhone и установленной PWA. Доступ к физическому устройству в этой
среде отсутствует. Браузер может удалить локальные данные при очистке сайта;
демоверсия предназначена для ознакомления и не для реального учёта.

На сохранённых данных показатели меняются с течением времени при выборе периода;
«Сбросить демо» создаёт исходный набор относительно текущей даты.
Известное предупреждение Vite о JS-чанке более 500 kB сохраняется; локальные
ресурсы распознавания намеренно входят в офлайн-кеш. Публикация и проверка
реального внешнего URL не выполнялись в рамках разработки.

Результаты выполненных проверок: [SALES_DEMO_VALIDATION.md](SALES_DEMO_VALIDATION.md).
