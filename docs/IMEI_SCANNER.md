# Локальный сканер IMEI

Кнопка камеры рядом с IMEI в `PurchaseForm` открывает сканер и при закупке, и при редактировании. Наведите камеру на экран `*#06#`, коробку или наклейку и нажмите **Распознать кадр**. Можно выбрать фото/скриншот из галереи и повернуть его. При нескольких результатах выберите нужный номер, сверьте с оригиналом и нажмите **Подтвердить IMEI**. До подтверждения форма не меняется. Сохранение закупки выполняется обычной кнопкой формы.

## Обработка и валидация

- Текст распознаёт Tesseract.js 6.0.1 с локальной английской моделью, подходящей для цифр и подписей IMEI. Числовые слова с уверенностью ниже 80% отбрасываются.
- Штрихкоды декодирует ZXing 0.21.3: Code 128, Code 39, ITF, QR, Data Matrix, PDF417. Полный кадр и перекрывающиеся области проверяются также после поворота, чтобы находить несколько этикеток.
- Принимаются только ровно 15 цифр с правильной суммой Luhn. Повторяющиеся цифры, неверные суммы, неполные/длинные номера и явно подписанные EID/MEID/ICCID/SN исключаются. Пробелы и дефисы внутри номера допустимы; строки не склеиваются. Нет замены букв на цифры, исправления контрольной суммы или перебора подстрок длинных идентификаторов.
- Все кандидаты требуют выбора и отдельного подтверждения. Luhn обнаруживает многие ошибки, но не доказывает принадлежность номера устройству или его подлинность: сверка обязательна.
- Строгие правила относятся к результатам сканера. Существующие правила ручного ввода (длина и дубли), доменные операции и формат сохранения сохранены. Подтверждение вызывает тот же обработчик изменения IMEI; черновик, проверка дублей, закупка и редактирование работают прежним путём.

## Локальность и ресурсы

Изображения обрабатываются в памяти браузера. Фото, распознанный текст и IMEI не загружаются на внешние серверы; сетевых OCR API нет. Object URL фото отзывается после декодирования. Изображения не записываются в IndexedDB, localStorage или резервные копии. Подтверждённый IMEI попадает в существующее поле и далее сохраняется штатной логикой формы.

OCR и штрихкоды выполняются в Web Workers. Камера запрашивается без аудио, предпочтительно задняя, с `playsInline` для Safari. Все дорожки останавливаются при закрытии/размонтировании, выборе галереи, захвате кадра и уходе приложения в фон. Если разрешение выдано уже после закрытия, поздний поток тоже сразу останавливается. Поздние результаты закрытой сессии игнорируются. OCR ограничен таймаутом 60 секунд; незавершённая инициализация Tesseract завершается освобождением воркера, когда библиотека вернёт его экземпляр.

`predev` и `prebuild` копируют worker, SIMD/обычное LSTM-ядро с встроенным WASM и модель `eng` из npm в игнорируемую папку `public/scanner-assets/`. URL содержит версии зависимостей. Артефакты сканера добавляют примерно 11 МБ до HTTP-сжатия; CDN-зависимостей во время работы нет. Генератор Service Worker включает их и отдельные JS-чанки в существующую офлайн-оболочку. Первичная установка кеша требует сети и свободного места; офлайн доступен после завершения установки. Очистка данных сайта или вытеснение кеша браузером потребует повторной загрузки.

Для предзагруженных статических файлов Service Worker использует `ignoreVary: true`: запросы JS-модулей с `Origin` должны находить предзагрузку и при `Vary: Origin`. Схема IndexedDB, финансы, импорт/экспорт, восстановление и исходная опубликованная сборка в корне не изменялись.

## Разработка и проверки

```sh
npm ci
npm test
npx playwright install chromium firefox webkit
npm run test:browser
npm run build
```

Браузерные тесты используют production-сборку под `/phonebooks/`, реальные OCR/WASM и ZXing, синтетические скриншоты и сгенерированные штрихкоды. Аппаратная камера и разрешения имитируются. Матрица: Chromium, Firefox, WebKit; 1280×900 и 390×844.

Новые тесты проверяют Luhn и границы извлечения, уверенность OCR, один/несколько IMEI, неверные и неполные номера, несколько повёрнутых штрихкодов, захват кадра, галерею, подтверждение/отмену, ручной ввод, сохранение и повторное открытие закупки/редактирования, дубли, ошибки камеры/файла/OCR, освобождение потоков, отсутствие внешних HTTP-запросов и OCR/штрихкоды после офлайн-перезагрузки. Существующие тесты резервных копий и восстановления запускаются без изменения.

Результат проверки 12 ноября 2026: `npm ci` — успешно; `npm test` — **31/31** (26 прежних и 5 новых); полный Playwright-прогон — **150/150** (78 прежних и 72 новых), без пропусков. Production build прошёл с относительным base и с `/phonebooks/`. Сохраняется предупреждение Vite о крупном основном чанке (~794 КБ). В cloud-окружении WebKit запускался через временный конфиг с библиотеками из официальных Debian-пакетов в рабочей папке; конфигурация проекта не менялась. Мобильная раскладка также проверена по скриншоту 390×844.

## Ограничения и ручная проверка

Реальные iPhone/iOS Safari и Android/Chrome в этой среде недоступны. WebKit на Linux и узкий viewport проверяют движок/раскладку, но не заменяют физическое устройство. До выпуска следует проверить:

1. Разрешение/отказ камеры, выбор задней камеры, возврат из фона, закрытие и исчезновение индикатора камеры на iOS и Android.
2. Реальный экран `*#06#` (одна/две SIM), блики/муар, мелкий текст коробки, фокусировку и повёрнутые фото.
3. Галерею iOS, EXIF-ориентацию и HEIC: поддержка HEIC зависит от браузера; при ошибке требуется JPEG/PNG. Максимум файла — 20 МБ, рабочее изображение уменьшается до 2400 px по длинной стороне и 3,6 Мп.
4. Офлайн после первоначальной загрузки ресурсов, холодный запуск PWA и скорость/память на слабом устройстве. Камере нужен HTTPS или localhost.

Автоматического постоянного распознавания видеопотока нет: пользователь запускает анализ кадра кнопкой. Размытые или слишком мелкие цифры могут не распознаться из-за строгого порога уверенности; используйте более близкое/чёткое фото или ручной ввод. Штрихкоды с нестандартными бинарными payload/GS1-полями, где IMEI не выделен как самостоятельный 15-значный номер, не разбираются по схеме производителя.

Зависимости: [Tesseract.js](https://github.com/naptha/tesseract.js), [Tesseract.js-core](https://github.com/naptha/tesseract.js-core), [модель eng](https://www.npmjs.com/package/@tesseract.js-data/eng), [ZXing](https://github.com/zxing-js/library). Лицензия ядра и уведомления worker копируются вместе с ресурсами; npm-версии закреплены в lockfile. `bwip-js` используется только для генерации штрихкодов в тестах.
