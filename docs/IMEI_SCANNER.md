# Локальный сканер IMEI

Камера рядом с IMEI открывает автоматический сканер в закупке и редактировании. Нажимать кнопку снимка не нужно. Один надёжный номер подставляется автоматически, сканер закрывается; несколько номеров показываются кнопками выбора. Галерея и ручной ввод сохранены. Подстановка не сохраняет закупку: сохранение выполняется штатной кнопкой формы.

## Распознавание

- Tesseract.js 6.0.1 использует полную локальную английскую модель вместо компактной `best_int`. Первый проход ищет текст, затем числовые строки увеличиваются и читаются отдельно, с нормализацией контраста и другим режимом сегментации. Галерея также проверяется в поворотах, если основной проход не нашёл надёжного номера.
- Результат OCR принимается при высокой уверенности (от 82), либо совпадении двух разных проходов с уверенностью не ниже 45 и максимумом не ниже 60. Неуверенный одиночный результат не подставляется. В видеопотоке OCR дополнительно должен подтвердить номер на двух разных захватах. Штрихкод с валидным IMEI принимается сразу.
- ZXing-C++ через `zxing-wasm` 3.1.6 работает в отдельном Web Worker: Code 128/39, ITF, QR, Data Matrix, PDF417; включены усиленный поиск, поворот, инверсия и несколько символов. WASM загружается только со своего сайта, CDN не используется.
- Принимаются ровно 15 цифр с правильной суммой Luhn; исключаются повторы одной цифры, неверные/неполные/длинные номера и явные другие идентификаторы EID/SN. Нет подбора контрольной суммы или замены букв на цифры в результатах OCR. Уточняющий цифровой проход повторно читает пиксели, а не исправляет строку. Luhn не доказывает подлинность устройства.

Видеопоток обрабатывается последовательно, без очереди тяжёлых кадров; штрихкод проверяется до OCR. Область рамки читается чаще, полный кадр — периодически. Камера запрашивается без звука, сначала задняя с высоким разрешением, затем с ослабленными ограничениями. Отказ в разрешении не вызывает повторных запросов. Поддерживаемая непрерывная фокусировка включается через capabilities.

## Данные и ресурсы

Фото и IMEI не отправляются на сервер. Изображение остаётся в памяти; URL галереи отзывается после декодирования. OCR/WASM и ZXing выполняются локально. Фото не сохраняется в IndexedDB, localStorage или резервной копии. Подставленный IMEI идёт в прежний обработчик формы, штатный черновик и сохранение; доменные правила закупок/финансов, схема IndexedDB и импорт/экспорт не изменены.

При закрытии, выборе галереи, подтверждённом результате или уходе в фон дорожки камеры останавливаются, воркеры освобождаются, таймеры и ожидания отменяются. Поздние потоки и результаты не меняют поле. Начавший инициализацию OCR worker освобождается после возврата экземпляра библиотекой. Операция ограничена 45 секундами.

`predev`/`prebuild` копируют worker, обычное/SIMD ядра с встроенным WASM, полную модель `eng` и ZXing reader WASM в `public/scanner-assets/` (генерируемая папка игнорируется Git). Новая модель имеет новый URL `accurate-v2`, чтобы не читать старую из кеша. Общий размер ресурсов — около 20 МБ до HTTP-сжатия. Все файлы включаются в существующую офлайн-оболочку; офлайн доступен после первоначальной установки кеша. Очистка или вытеснение кеша браузером потребуют повторной загрузки.

## Проверки

```sh
npm ci
npm test
npx playwright install chromium firefox webkit
npm run test:browser
npm run build
```

Playwright использует production-сборку под `/phonebooks/`, настоящие OCR/WASM и ZXing, Chromium/Firefox/WebKit на 1280×900 и 390×844. Камера/разрешения имитируются. Проверяются автоматическое заполнение и закрытие, видеопоток без кнопки снимка и повторное чтение кадров, несколько IMEI, сохранение/перезагрузка/редактирование, дубли, поворот штрихкодов, галерея, ошибки, освобождение камеры, офлайн и отсутствие внешних запросов. Дополнительно с разными IMEI проверяются мелкий/наклонный текст этикетки, серый текст, JPEG, шрифт с засечками и тёмный экран.

Для независимой ручной QA использованы фотографии с Wikimedia Commons: [коробка ASUS](https://commons.wikimedia.org/wiki/File:Barcodes_(Asus_mobile_phone_box).jpg) и [наклейка Alcatel](https://commons.wikimedia.org/wiki/File:Alcatel_OT_217D_mobile_phone_IMEI_sticker.jpg). На обеих проверены напечатанные номера в Chromium и WebKit. Эти фото не добавлялись в исходники/публикацию и не использовались как записи склада.

## Что проверять на устройстве

Физические iPhone/iOS Safari и Android/Chrome здесь недоступны. Движок WebKit не заменяет устройство: фокусировку, блики, муар, системную галерею/HEIC, скорость на слабом телефоне и исчезновение индикатора камеры нужно проверить вручную. HEIC зависит от браузера; при ошибке используйте JPEG/PNG. Максимум файла 20 МБ, рабочее изображение — до 3200 px и 6 Мп. Камере нужен HTTPS или localhost. Размытые/закрытые цифры и нестандартные бинарные/GS1 payload могут не распознаться; ручной ввод остаётся доступен.

Проверка текущей версии: 33/33 модульных, 96/96 браузерных сценариев сканера, 4/4 проверки независимых фотографий. В полном наборе 174 сценариев один штатный тест восстановления WebKit-mobile потребовал синхронизации фикстуры: теперь перед редактированием ожидается применение загруженного названия в поле. Продуктовая логика настроек и восстановления не менялась.
