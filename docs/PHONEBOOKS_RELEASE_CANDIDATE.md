# Кандидат PhoneBooks 2.0 для приёмки

Сборки относятся к [черновику PR #10](https://github.com/bikmako/phonebooks/pull/10). SHA лежит в `build.json` каждого архива. Перед распаковкой сверьте файлы с `SHA256SUMS.txt`. Работайте в отдельном профиле браузера с синтетическими данными.

## Установка тестовой версии

### Solo

1. Для проверки с ПК распакуйте архив Solo, откройте терминал в каталоге с папкой `phonebooks` и запустите `python -m http.server 4173 --bind 127.0.0.1`.
2. Откройте `http://127.0.0.1:4173/phonebooks/`. Для iPhone и Android используйте тот же каталог на отдельном согласованном HTTPS-хосте. Установите приложение через меню браузера с именем «PhoneBooks ТЕСТ».
3. Для обновления сначала установите исходную сборку на этом же тестовом адресе и создайте синтетические записи и полную копию. Затем замените файлы только в каталоге тестового сервера. В открытой версии дождитесь уведомления и примените обновление после сохранения черновика. После перезапуска проверьте остатки, кассу, историю, ремонты, настройки, копии и черновик. Отключите сеть и запустите приложение повторно.
4. Для репетиции прерывания остановите доставку одного файла новой версии. Проверьте, что предыдущая сборка открывается офлайн со своими данными. Восстановите доставку и повторите обновление. Для сценария с новым адресом используйте предварительно скачанную полную копию и проверьте результат до закрытия исходного приложения.

Архивы для поэтапной проверки iPhone лежат в артефакте CI `iphone-update-device-test`. Для сборки того же набора на проверенных опубликованных байтах запустите команды ниже из репозитория. Полученный снимок обслуживается локально, его 22 файла и Service Worker сверяются по SHA-256.

```sh
node tools/capture-production-fixture.js
PHONEBOOKS_USE_PUBLISHED_FIXTURE=1 npm run test:updates -- --grep 'legacy'
PHONEBOOKS_USE_PUBLISHED_FIXTURE=1 node tools/prepare-device-test.js
```

В PowerShell задайте `$env:PHONEBOOKS_USE_PUBLISHED_FIXTURE = '1'` перед запуском команд, затем удалите эту переменную после проверки. Готовые архивы Solo, Team и Demo также публикуются как артефакт проверки `phonebooks-acceptance-builds` внутри PR.

Исходный публичный Service Worker имеет версию `phonebooks-v9-b7003a21742132e4`. Тесты загружают синтетический снимок в изолированную IndexedDB и сверяют состояние, точки восстановления, метаданные, тему и черновики до и после перехода. CI дополнительно прогоняет воспроизводимую исходную сборку из закреплённого коммита.

### Team

Архив включает `dist-team`, адаптер Render и миграции. Для внутренней проверки разработчика в репозитории запустите `npm run test:team`. Для внешней приёмки используйте отдельный Render Web Service и существующий Supabase `phonebooks-staging` по [инструкции внешней приёмки](PHONEBOOKS_TEAM_STAGING_WORK.md). Сохраните SHA прежней сборки и контрольную копию перед применением миграций.

### Demo

1. Распакуйте архив Demo. Нужен Node.js 20.19+ и npm. В каталоге архива выполните `npm ci --include=dev` и `npm run demo`.
2. Откройте `http://localhost:4497/` для Solo или `http://127.0.0.1:4498/` для Team. В приложении есть переход между этими адресами. Регистрация отсутствует. В режиме Team каждый браузер получает своё учебное предприятие и тестовых коллег.
3. Для новой истории Solo используйте отдельный профиль или сбросьте учебные данные в настройках. Team держит данные в локальной памяти процесса. Перезапуск очищает все учебные предприятия. Одновременно поддерживается до 12 гостевых контекстов на один процесс.
4. Из исходников демосборка готовится командами `npm run build:demo` и `npm run demo`. Публичное развёртывание требует отдельного решения по хостам, гостевым сессиям и лимитам. Эти адреса предназначены для проверки на ПК.

### Отдельный HTTPS-стенд Demo на Render

Создайте бесплатный Web Service `phonebooks-demo-staging` из ветки с адаптером Demo. Укажите `PHONEBOOKS_DEMO_ORIGIN=https://phonebooks-demo-staging.onrender.com` для сборки и запуска. Команда сборки `npm ci --include=dev && npm run build:demo`, запуска `npm run demo`, проверка здоровья `/healthz`, автоматический деплой выключен. Стенд открывает `/solo/` и `/team/` и перенаправляет корневой адрес в Solo.

Solo хранит синтетические данные в отдельной IndexedDB. У Team собственная временная база в памяти и отдельное предприятие на гостя. Сессия длится 45 минут, одновременно доступно до 12 гостевых пространств, в каждом до 100 попыток проведения операций. Перезапуск Render сбрасывает состояние Team. Переменные Supabase и рабочие резервные копии для этого сервиса не требуются.

Demo использует отдельный origin, отдельную IndexedDB Solo и локальный PGlite Team со своими миграциями. Экспорт, перенос, приглашения и регистрация закрыты. Рабочий импорт отклоняет помеченный учебный файл. В демо есть несколько месяцев операций, ремонты, возврат и компенсация, бронирование, товары шести основных групп, пользовательская категория и возрастные партии.

## Изменения по результатам аудита

| Проверка | Результат |
| --- | --- |
| Один комбинированный чек | Сводка Solo, Excel/CSV и детальная аналитика теперь используют один счётчик заказа. Средний чек рассчитывается по проведённым чекам. Возвраты корректируют выручку своего периода. |
| Расходы и маржа | Сводка и финансовый экспорт Solo включают списания и разницу при возвратах поставщику. Сверены чистая прибыль, касса и FIFO по журналу. |
| 320 px | Устранено растягивание контейнера и поля поиска на складе Solo. Проверены разделы двух режимов в Chromium, Firefox и WebKit. Сценарии форм и диалогов проходят отдельным браузерным набором. |
| Точки восстановления | Убрано второе скачивание во время подтверждения импорта. Предварительная копия выгружается по клику из зафиксированного исходного снимка. Проверка актуальности, два подтверждения, журнал и внутренняя копия сохранены. |
| Импорт Excel и локальная разработка | Обновлены `fflate` и Vite, а серверы разработки и превью привязаны к loopback. Проверены ограничения формата, формулы, дубликаты, повреждённые файлы, большой импорт и откат. |
| Разрешения Team | Миграции 001–017 создают 22 закрытые таблицы с RLS и 27 публичных RPC, доступных аутентифицированной роли. Проверены серверные права, разделение предприятий и полей, отзыв доступа, идемпотентность и конфликт операций. |

В проверенных исходниках нет ручного вывода HTML для введённых пользователем данных. Проверка зависимостей npm после обновления не выявила известных уязвимостей на момент прогона. Закрытые пакеты и рабочие резервные копии в артефакты не входят.
