# PhoneBooks 2.0 — этап 8. Универсальный склад

## Учёт товаров

В обоих режимах доступны смартфоны, ноутбуки, планшеты, игровые приставки, умные часы, компьютеры, комплектующие, аксессуары и пользовательские категории. Пользовательские характеристики поддерживают текст, число и логическое значение. Формы показывают поля выбранной категории.

В Solo раздел «Скупка → Другие товары» проводит закупку, ремонт поштучного товара и продажу по выбранному счёту. Эти записи входят в остатки, кассу, историю, график и прибыль. Старые карточки смартфонов и партий аксессуаров доступны на прежних вкладках. В Team все категории используют общий серверный склад, включая сотрудников и их индивидуальные права.

Стоимость количественных товаров списывается по очереди поступления партий. Расход на завершённый ремонт увеличивает себестоимость поштучного товара. Плановая цена подставляется в форму продажи и может быть изменена перед проведением. В Team новая миграция сохраняет цену и характеристики при переносе копии из Solo.

## Управление складом

- Поиск в шапке ищет по складу и истории. По совпадению в характеристике можно перейти к карточке. Team выполняет поиск истории на сервере и фильтрует выдачу по правам.
- Список поддерживает фильтрацию по категориям и статусам, сортировку по названию и остатку. Team сохраняет существующие фильтры смартфонов, аксессуаров и других категорий.
- Массовое редактирование показывает старые и новые значения. Оно меняет плановую цену или одну общую характеристику товаров выбранной категории. В Solo у прежних карточек смартфонов и аксессуаров массово меняются цены. На одной операции можно выбрать до 100 товаров.
- Предпросмотр отменяется без записи. После подтверждения отмена доступна, пока открыт экран и совпадают версии. Для старых карточек Solo проверяется текущее значение цены. Позднее изменение карточки останавливает весь откат. Team дополнительно сохраняет квитанцию запроса и проверяет права при повторе.
- Название предприятия Team редактирует владелец в разделе «Команда». Изменение попадает в журнал. Solo сохраняет существующий редактор названия в настройках.
- Team использует тот же локально поставляемый сканер IMEI, что и Solo. Для него включены загрузка одноимённых ресурсов с origin приложения и компиляция WebAssembly. Фото и кадры читаются в браузере.

## Совместимость и запуск

В Solo старый каталог из метаданных доступен сразу. При первом сохранении из нового интерфейса каталог попадает в основное состояние IndexedDB. Новые операции и карточки сохраняются вместе. Предыдущие копии читаются. Для учёта по новому журналу следует использовать версию этапа 8 или новее.

Для Team требуется миграция [202611260012_phonebooks_warehouse.sql](../../supabase/migrations/202611260012_phonebooks_warehouse.sql) поверх миграции этапа 7. Серверные проверки прав, версий и рабочего пространства применяются в транзакции. Внешний стенд обновляется отдельным шагом.

```bash
npm ci
npm run dev
npm run build
npm run build:team
npm test
npm run test:team
```

Чтобы повторить проверку склада, запустите `npm run test:team -- warehouse.spec.js`. Для сохранения снимков задайте `PHONEBOOKS_WAREHOUSE_SHOTS=docs/design/warehouse`. Тестовый HTTPS использует OpenSSL.
