# Повторный аудит экспорта, импорта и восстановления — PR #2

Ветка: `migration/safe-local-backups`. Проверяется продолжение коммита `f4291afc550bdf56adbe897591e45dd2e9913a16`.
Все данные синтетические; тесты обращаются только к localhost. Netlify, клиентские данные, main, конфигурация публикации и старая сборка не изменяются. Коммит содержит `[skip ci] [skip netlify]`. Merge/deploy не выполняются.

## Исправления по результатам аудита

1. **Коллизии полных recovery-копий.** Ранее одинаковый ключ локальной и входящей исторической копии приводил к перезаписи одной из них. Теперь разные значения сохраняются под разными ключами; новая копия получает UUID. Дата отображается отдельно от суффикса. Регрессионный тест проверяет сохранность обеих историй и новой предварительной копии.
2. **Непереносимый экспорт большого размера.** Экспорт раньше не ограничивался, хотя импорт отклоняет файлы больше 32 МиБ. Теперь в приложении и readonly-скрипте старого origin проверяется размер фактически скачиваемого JSON с отступами в UTF-8. Слишком большая копия не выдаётся за пригодную к импорту. Это также безопасно блокирует импорт, если его предварительную копию нельзя выгрузить. Автоматического удаления recovery-копий не добавлено.
3. **Некорректные календарные даты.** `Date.parse` допускал нормализацию 30 февраля и неоднозначные строки в зависимости от движка. Теперь требуются ISO-дата/ISO-время и существующий календарный день. Неверные файлы отклоняются до записи.
4. **Повреждённый журнал отката.** Ранее восстановление доверяло списку ключей журнала и могло очистить черновики до ошибки либо записать чужой ключ. Теперь список валидируется до первой мутации; повреждённый журнал остаётся на месте, запуск блокируется, данные не стираются.
5. **Мобильная доступность подтверждения.** Файловое поле скрыто внутри кликабельного label, кнопки диалога на узком экране размещаются вертикально. Геометрия кнопок и строки загрузки проверяется тестом, без принудительных кликов.

Новых бизнес-функций, облака, аккаунтов или лицензирования нет.

## Тестовые данные

Детерминированные по сценарию данные создаются действующими доменными функциями; значения id и времени генерируются заново для изоляции запусков:

- Два счёта с начальным остатком, три телефона, проведённая и отменённая продажи.
- Два вида аксессуаров, партии по 15 единиц, продажа двух позиций и списание.
- Расход аренды, перевод между кассой и банком, пополнение и снятие.
- 15 записей аудита, неизвестное дополнительное поле состояния, обычная точка восстановления и дополнительные метаданные.
- Настоящие ключи `phonebooks.draft.phone-new` и `phonebooks.draft.sale-new`, включая позиции аксессуаров в продаже; тема оформления.

Сравниваются полные JSON-значения состояния и payload точек, метаданные и строки localStorage, а не только количество записей. Служебный `lastSaved` после импорта обновляется; recovery-записи добавляются ожидаемым образом. Порядок записей stores сравнивается в порядке курсора IndexedDB. Необязательные свойства `undefined` не являются частью формата JSON и нормализованы в тестовой фикстуре.

## Что проверяется браузером

- Полный экспорт → импорт того же файла → перезагрузка → повторный экспорт с точным сравнением данных.
- Отмена предпросмотра без изменения stores/localStorage, отдельные подтверждения и предварительное скачивание.
- Замена данных и восстановление полной предварительной копии, сохранение полей расширения, истории, финансов и черновиков.
- Обычная точка восстановления: предпросмотр/отмена/подтверждение; черновики, которые такой legacy-снимок не содержит, сохраняются в полной предварительной копии.
- Открытие семи разделов на реалистичной базе без ошибок JavaScript; открытие форм после восстановления и проверка восстановленных черновиков.
- Восстановление искусственно оставленного журнала при перезагрузке до редактирования.
- Реальные вызовы Storage и IDBObjectStore с искусственно вызванным QuotaExceededError; сравнение базы и черновиков после отката и после перезагрузки.
- Повреждённые JSON/версии, устаревший предпросмотр, повреждённое current без создания пустой базы.
- Офлайн-запуск и экспорт с Service Worker под `/phonebooks/`.
- Readonly-выгрузка из локальной неизменённой старой сборки, перенос между origin и отсутствие создания базы на пустом origin.

Node-регрессии дополнительно проверяют версии/структуру/ссылки/вложенные данные, отказы резервирования и отката, отмену во время ожидания копии, сохранение исторических отменённых продаж, лимит UTF-8, календарь, коллизии и повреждённый журнал.

## Воспроизведение и среда

Node 24.22.1, Playwright 1.65.0; Chromium 158.0.8127.18, Firefox 159.0, WebKit 27.2 (сборки Playwright). Тесты не запускались на браузерах, установленных у клиентов.

```sh
npm ci
npx playwright install --with-deps chromium firefox webkit
npm test
npm run test:browser
```

В управляемой среде браузеры сохранены в `/workspace/work/browser-cache`. Отсутствующие официальные Debian-библиотеки распакованы локально в `work/browser-libs`, WebKit использует их из своей локальной runtime-папки; конфигурация ОС не менялась. Firefox потребовал запуска вне файловой песочницы. Проверка наличия библиотек Playwright была отключена только после подготовки библиотек; фактический запуск и сценарии каждого движка проверяются тестами. Эти переменные окружения не включены в конфигурацию проекта.

Диагностические прогоны выявили недостающие зависимости среды и ошибки сравнения тестовой фикстуры (порядок ключей stores и `undefined`, отсутствующий в JSON). Также устранена гонка тестов с автоматической перезагрузкой приложения (Firefox/WebKit): перед чтением базы ожидается новый документ, без повторных попыток или маскировки исключений. Эти проблемы исправлены; итоговые результаты выше относятся к повторным прогонам окончательного кода, без скрытых retry или пропусков.

## Заключение и оставшиеся ограничения

Готово к ревью PR и контролируемой миграции в протестированных движках по инструкции с проверенной внешней копией. В перечисленных сценариях потери данных не обнаружено. Разрешение на merge или публикацию из этого заключения не следует. Готовность к массовой миграции на реальных Safari/iPhone требует отдельной проверки этих устройств.

Сохраняются ограничения: нет общей транзакции IndexedDB/localStorage (используется журнал); Web Locks нужны для импорта; старые вкладки нужно закрыть; браузер не подтверждает физическое сохранение скачанного файла. Копии не подписаны/не зашифрованы. Очистка origin удаляет и внутренние копии; recovery-копии расходуют квоту и не очищаются автоматически. Для базы больше 32 МиБ нужен отдельный проект масштабируемого формата; текущая версия безопасно останавливает такой экспорт/импорт.

Не проверены реальный Safari/iOS, системное удаление/вытеснение данных, внезапное выключение устройства и физический сбой диска. Перезагрузка с журналом и искусственные исключения записи покрывают программные ветки восстановления, но не доказывают устойчивость к любому аппаратному сбою. Реальные данные клиентов не использовались.
