# Проверка PhoneBooks DEMO

Ветка: `feat/isolated-sales-demo`. Базовый main: `832972e5407a6a08894f1df5e475cb7a5cf02ac1` (после PR #5).
Дата: 13 ноября 2026. Node.js 24.22.1, Playwright 1.65.0.

- Модульные тесты: 55/55 (`npm test`).
- Проверка двух независимых сборок: 1/1 (`npm run test:builds`).
- Основная версия: Chromium desktop + Android Chromium — 74/74.
- Firefox desktop + iPhone WebKit — 74/74 после точечного повтора трёх сценариев с превышением лимита времени.
- DEMO: desktop Chromium, Android Chromium, iPhone 13 WebKit, iPhone SE WebKit — 36/36 после повтора одного длинного сценария; дополнительно повторены первый запуск и цикл закупка → продажа → сброс во всех четырёх профилях (8/8).

Проверены целостность ссылок и партий, выручка, себестоимость, прибыль с ремонтом и списанием, остатки счетов, автоматическое заполнение при первом запуске, сохранение после перезагрузки, закупка и продажа, аксессуары, расходы, пополнение, подтверждение и отмена сброса, очистка демоключей, откат неудачного сброса, отказ устаревшей вкладке, восстановление повреждённой демобазы, запрет API переноса и отсутствие его UI.

Проверки изоляции помещали sentinel-значения в production IndexedDB, legacy localStorage, тему, черновики и production-кеш. После работы и сброса DEMO они сохранялись. Запуск DEMO на подставленном origin `https://bikmako.github.io` блокировался до открытия баз и регистрации SW.

Офлайн-проверки запускали настоящие OCR и Code128 из локальных WASM/языковых ресурсов; сканер открывался после отказа камеры, распознавал изображение и заполнял IMEI, закупка сохранялась после офлайн-перезагрузки. Основной набор отдельно проверяет QR, поток камеры с тестовыми кадрами и освобождение ресурсов.

В окружении не было части библиотек WebKit: официальные Debian-пакеты распакованы в рабочий каталог и подключены к пользовательскому браузерному runtime. Запуски WebKit использовали `PLAYWRIGHT_SKIP_VALIDATE_HOST_REQUIREMENTS=1`, поскольку dlopen-проверка Playwright читает системный ldconfig и не видит пользовательские библиотеки. Сам WebKit запускался, тесты не пропускались.

При одновременном выполнении разных наборов четыре длинных сценария WebKit превысили общий лимит теста 60 секунд (один DEMO, три основной версии). Отдельные повторы одним worker с лимитом 120 секунд прошли: сценарий DEMO за 24,3 секунды, основные за 30,2 / 28,6 / 24,1 секунды. После исправлений функциональных ошибок в проверенных сценариях не осталось. Для новых длинных demo-сценариев установлен общий лимит 120 секунд.

Ограничения: физический iPhone/камера и установка реальной PWA не проверены; первый визит требует сети для ресурсов распознавания. Контакт продавца оставлен пустым и настраивается в `.env.demo.local`. Публикация не выполнялась. Предупреждение Vite о большом JS-чанке сохраняется.

Инструкция публикации: `docs/SALES_DEMO.md`. Загружать только `dist-demo/` в новый HTTPS-проект с отдельным origin. Не использовать `bikmako.github.io/phonebooks-demo/` — это тот же origin.

## Команды финальных повторов

```bash
PLAYWRIGHT_SKIP_VALIDATE_HOST_REQUIREMENTS=1 npm run test:demo:browser -- --grep 'first launch|purchase, completed' --workers 1
PLAYWRIGHT_SKIP_VALIDATE_HOST_REQUIREMENTS=1 npm run test:browser -- --last-failed --project iphone-webkit --workers 1 --timeout 120000
npm run test:builds
npm test
```

`--last-failed` использовал результаты полного предыдущего прогона. Для
независимого повторения этих трёх основных сценариев можно задать
`--grep 'realistic data: exact round-trip|purchase, repair cancellation|repeat repairs, correction'`
вместо `--last-failed`. Итого проверено 148 сценариев основной версии и 36 DEMO,
55 модульных тестов и проверка артефактов обеих сборок. `git diff --check` чистый.

Обе сборки также проверены с base по умолчанию и с base `/phonebooks/` / `/demo/`.
Генератор синтетических записей отсутствует в оплачиваемой сборке. Исходные файлы
готового сайта, `public/`, `.github/workflows/` и удалённая ветка main не менялись.
